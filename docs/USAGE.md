# 连接与使用

本文介绍应用配置。开发和打包见[构建与发布](../BUILD.md)，各条链路的实现见[项目结构与执行流程](ARCHITECTURE.md)。

## 准备条件

| 使用方式 | 条件 |
| --- | --- |
| 连接远程后端 | 可从手机访问的 NKAS API v2 后端；Android 8.0+ 或 iOS 15.0+ |
| 实时控制远程 Android | 已开启 ADB 的 Android 目标，网络可达，且允许该客户端的 ADB 身份 |
| Android 本机部署 | Termux、运行命令权限及足够的存储和网络条件；无线调试配对需要 Android 11+ |
| iOS 安装 | 有效签名的应用；未签名 IPA 需通过自己的签名方案安装 |

首次使用按应用提示完成 STAR 验证，验证对象是后端仓库 `megumiss/NIKKEAutoScript`。STAR 验证、后端安全入口、Tailscale 节点注册和设备 ADB 授权各自独立。

## 连接后端

在“设置 → 后端地址”输入服务地址并点击“保存并连接”。例如 `http://192.168.1.20:12271` 或 `https://nkas.example.com`。地址必须从手机所在网络可达；手机上的 `127.0.0.1` 指向手机本身。

连接成功后可查看实例、队列和日志，修改任务与调度。“更新”页面操作的是后端程序，移动应用本身需安装新的 APK 或 IPA 更新。

### 安全入口

后端安全入口默认关闭，可在“部署 → Webui → SecurityEntryEnabled”开启。启用后，将部署页生成的完整链接填入后端地址：

```text
https://nkas.example.com/entry/<部署页生成的入口密钥>
```

从本机复制的链接用于远程连接时，把主机地址替换成手机可访问的 IP 或域名，保留完整 `/entry/...` 路径。入口不会自动开放监听、配置反向代理或穿透网络，远程访问仍需自行配置。

应用会拆分并安全保存入口密钥，为该后端的 API、图片及 WebSocket 请求携带凭据。普通设置显示根地址；入口密钥保存在 Android 加密存储或 iOS 本设备 Keychain 中。不要分享完整入口链接。

“重新生成”会撤销旧入口、Cookie 与 Bearer 凭据；执行操作的客户端保存新入口，其他远程客户端需重新填写。关闭入口保护会保留后端密钥，再次开启沿用；“还原默认”保留入口设置。这些入口操作不停止自动化任务。入口保护不覆盖独立的 ADB/scrcpy 连接。

## 配置实时控制

在“设置 → 控制连接”选择“远程 Android”，填写目标 ADB 地址并保存：

| 地址类型 | 示例 |
| --- | --- |
| IPv4 | `192.168.1.30:5555` |
| ADB 前缀 | `adb://192.168.1.30:5555` |
| IPv6 | `[2001:db8::30]:5555` |
| Tailscale IP / MagicDNS | `100.x.x.x:5555` 或 `android-device:5555` |

端口以目标实际配置为准，无线调试端口可能变化。若设备弹出 ADB 授权提示，需要在目标端确认。

后端实例决定任务、日志和截图来源；控制连接决定实际接受触摸输入的 Android 设备。两者应由使用者核对匹配，切换实例不会自动改写控制地址。

在“画面”页点击“连接设备”启动实时控制。首帧到达前显示后端截图，首帧可用后切换为实时画面；断开或失败后恢复两秒一次的截图请求，后端不可用时显示错误或空态。截图预览不提供实时触控。

支持单指点击、长按、滑动、返回、主页和文本输入。文本上限为 300 UTF-8 字节，实际字符支持取决于 Android 输入法与 scrcpy。控制连接设置从画面页打开时会停止当前控制，返回后需点击“连接设备”重新连接。

### 使用 Tailscale

1. 在控制连接中开启 Tailscale，设置节点名。
2. 在 [Tailscale 管理后台](https://login.tailscale.com/admin/settings/keys)创建 AuthKey（以 `tskey-auth-` 开头），使应用加入目标设备所在的 tailnet。
3. 首次注册或清除身份后填写 AuthKey，点击“验证连接”；已保存节点身份时可以留空。
4. 确认 tailnet ACL 允许访问目标 ADB 端口，再连接画面。

应用内 Tailscale 为 ADB 控制链路提供转发，不要求安装系统 Tailscale 客户端或授权 VPN。它不会接管后端 HTTP/WebSocket 流量；若后端只有 tailnet 地址，手机还需要可访问该地址的系统网络、VPN 或隧道。

访问目标局域网地址时，需要 Tailscale 子网路由器发布对应网段，并在 tailnet 中批准路由。直接使用目标 Tailscale IP 或 MagicDNS 时，也需满足对应访问规则。

AuthKey 仅用于内存中的注册请求。节点状态保存在应用私有目录并排除系统备份；“清除身份”会停止活动连接并删除本地节点状态，之后需重新注册。在注册等待期间可取消连接。

## Android 本机部署

1. 在“初始化 NKAS”中安装并打开 Termux，按提示授予运行命令权限。
2. 按初始化步骤准备工具、下载后端源码、创建配置、安装运行环境并启动服务。初始化日志显示各步骤进度和错误；失败后可重试。
3. 在 Android 系统设置开启无线调试，通过初始化页完成配对与连接。
4. 在“设置 → 后端地址”选择“使用本机 Termux 部署”；需要本机控制时，在控制连接选择“本机虚拟屏幕”。

本机后端通过 Termux 和 proot-distro 运行。服务默认监听 `127.0.0.1:12271`，运行配置位于 Termux 的 `$HOME/.nkas/settings.env`，其中 `NKAS_WEBUI_HOST` / `NKAS_WEBUI_PORT` 决定服务实际监听地址和端口。

本机后端开启安全入口后，应用通过已授权的 Termux 命令读取入口凭据，并可在凭据变更后重新读取。手动填写地址始终按远程连接处理，即使填写回环地址也不会自动读取本机凭据；可用“使用本机 Termux 部署”显式切回本机模式。

本机虚拟屏幕使用原生 ADB 与 scrcpy，导入已配对的本机身份，并与远程控制身份分开保存；不经过 Tailscale。虚拟屏幕是否可用取决于系统支持。iOS 不提供 Termux 部署或本机虚拟屏幕。

## 后台与故障排查

Android 在活动控制期间使用前台服务；若后台断线，回到前台后恢复连接。iOS 进入后台会停止视频与转发，回前台后重新建立仍被请求的控制会话。网络故障会触发有限次数的自动重试，连续失败后可手动连接。

| 现象 | 检查方向 |
| --- | --- |
| 后端无法连接 | 地址是否从手机可达、服务监听、反向代理与防火墙、API 是否为 v2 |
| 安全入口无效 | 是否粘贴完整入口、是否被重新生成；远程客户端填写新入口 |
| 后端可连但实时画面失败 | 单独检查 ADB 目标地址、端口、授权和 Tailscale ACL |
| 实时控制可用但任务或日志失败 | 单独检查后端连接、安全入口和所选实例 |
| 本机部署无法读取 | Termux 是否初始化、运行命令权限、服务配置和日志 |
| 文本或虚拟屏幕不符合预期 | Android 输入法、系统及 scrcpy 的能力限制 |

提交问题时附上应用版本、平台、目标设备、使用的连接方式和复现步骤，并去除完整入口、AuthKey、私钥及其他凭据。
